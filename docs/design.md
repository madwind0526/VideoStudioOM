# VideoStudioOM 설계서 (초안)

작성: 2026-10-19. 상태: 사용자 검토 대기. 사용자 요구 6가지를 그대로 따른다.

## 1. 목표와 원칙

- OpenMontage(영상 엔진)와 SongYUE2(음악) 위에 얹는 **영상 제작 GUI**. 둘을 최대한 그대로 쓴다.
- **줄거리, 시나리오(장면 구성), 대본은 LLM 텍스트 호출로 만든다**(MusicAutomation이 주제로 가사를 만드는 방식). 단계마다 사람이 검토/수정/승인하고 수정본이 다음 단계의 입력이 된다. **OpenMontage는 이미지/영상/음성/음악/합성 도구로만 쓴다.** 도구 권한을 가진 에이전트는 쓰지 않는다(개정 2026-10-19, 근거 `docs/spike-agent.md`). GUI의 일은 설정 → LLM 생성 → 산출물 검토/수정 → 승인/재생성 → 라이브러리다.
- 중간 산출물은 모두 **폴더의 파일**로 남기고 GUI와 파일 탐색기 양쪽에서 읽고 고칠 수 있다(SongYUE2 라이브러리 방식).
- 유료 API 없음. 로컬 모델(Krea, H3, RTX, Qwen3-TTS, SongYUE2)과 Claude/Codex 구독만 쓴다.

## 2. 구성

```
브라우저 UI (React + TS + Vite, :5184 dev)  ── REST/SSE ──  Node 백엔드 (:4314)
                                                              ├ 설정/프로젝트/파일 저장소
                                                              ├ LLM 텍스트 호출 (claude / codex / opencode CLI, ollama)
                                                              ├ 엔진 (server/engine: ComfyUI :8190/:8188 REST+웹소켓, 그래프, 도구)
                                                              └ SongYUE2 (:4311: 음악, 효과음, 음성 엔진)
프로젝트: projects/<id>/ (기본 위치는 앱 폴더의 projects)
```

- **UI**: SongYUE2 스타일. 미니멀, 아이콘(lucide) 중심. 좌측 아이콘 메뉴 / 상단 메뉴(프로젝트, 단계 표시, LLM 선택) / 하단 시스템 메시지 줄(진행, 오류, 에이전트 로그 요약). 한국어 UI, 라이트/다크.
- **백엔드**: Node(웹 프레임워크 없음), MemoReader/MusicAutomation과 같은 구조(`server/`, `shared/`). LLM 선택 계층은 MusicAutomation의 `llm.mjs`, `llm-cli.mjs`를 복사해 사용(순서: claude-cli, codex-cli, opencode-cli, ollama, 기본 claude-cli). 코드는 이 저장소로 복사하고 원본 커밋을 주석에 남긴다(경로 import 금지).
- **엔진**: `server/engine/`가 ComfyUI(그래프 제출, 진행률, 취소, 다운로드)와 SongYUE2를 Node에서 직접 호출한다. 2026-10-20에 OpenMontage와 Python 브릿지를 걷어냈다(`docs/engine.md`).
- **진행 상황**: LLM 호출과 도구 실행의 상태, 그리고 `projects/<id>/`에 쓰이는 파일을 백엔드가 감시해 SSE로 UI에 전달한다.
- **접근 보호**: 서버는 `127.0.0.1`만 열고, 요청의 `Origin`/`Host`가 앱 주소와 다르면 거부하며, 시작 시 만든 토큰을 쓰기/실행 요청에 요구한다(SongYUE2 백엔드의 외부 Origin 차단 방식 참고).

## 3. 프로젝트 폴더 (단일 진실 원천)

`E:\Claude\VideoStudioOM\projects\<id>\`(2026-10-27에 `E:\Claude\OpenMontage\projects`에서 옮김)에 OpenMontage 형식의 프로젝트 폴더를 두고 GUI 전용 `studio/`를 추가한다. OpenMontage의 Backlot 보드는 읽기 전용이라 환경변수 `OPENMONTAGE_PROJECTS_DIR`를 이 폴더로 지정하면 같은 폴더를 볼 수 있다.

```
projects/<id>/
  project.json                         OpenMontage 프로젝트 표식
  studio/
    settings.json                      이 프로젝트의 설정(전역 기본값을 덮어씀)
    topic.md  synopsis.md              주제, 전체 줄거리 (사용자 편집 가능)
    approvals.json                     단계별 승인 기록(시각, 승인한 내용의 해시)
  artifacts/
    scene_plan.json  script.json       OpenMontage 스키마(schemas/artifacts/*.schema.json)로 검증하는 시나리오(장면 구성)와 대본
  assets/
    images/ video/ audio/ music/       장면별 이미지, 클립, 음성, 노래
  renders/final.mp4
```

- 편집은 JSON 산출물의 필드 단위 폼이 기본이고, 저장 전에 OpenMontage 스키마로 검증한다. 읽기 쉬운 `.md` 보기는 파생 뷰로 제공한다(원본은 JSON).
- `artifacts/*.json` 파일이 정본이다. OpenMontage 체크포인트(`checkpoint_<stage>.json`)는 만들지 않는다. 시험 결과(2026-10-19) 파이프라인 이름 없이 `write_checkpoint`로 `script`/`scene_plan`을 쓰는 것은 가능하지만(스키마 검증만 거침), `cinematic` 등 파이프라인을 지정하면 앞 단계(research, proposal)가 없다며 거부된다. Backlot 보드 연동이 필요해지면 그때 파이프라인 이름 없이 체크포인트를 미러링한다.
- 단계 파일을 편집하면 그 이후 단계의 `approvals.json` 기록이 무효가 된다(승인한 내용의 해시가 달라짐).
- 전역 기본 설정은 `data/settings.json`.

## 4. 요구사항 매핑

### 4.1 UI 틀 (요구 1)
화면 구성은 SongYUE2를 따른다(색과 크기는 실행 중인 SongYUE2에서 읽은 값: 배경 `#171817`, 포인트 `#8ed8c8`, 사이드바 188px, 반경 8px, 시간 글꼴 Orbitron). **줄거리, 시나리오, 대본, 이미지, 오디오, 동영상은 한 프로젝트의 구성품**이라서 따로 최상위 메뉴를 두지 않는다. **좌측**: 로고(VideoStudioOM by madwind), 메뉴 `만들기 +` / `프로젝트` / `라이브러리`(완성된 동영상만) / `좋아요`(좋아요한 완성 동영상만), 구분선 아래 **최근 프로젝트**(최근에 연 순서), 맨 아래에 **설정**. **상단**: 왼쪽에 `작업 공간 > 현재 화면 > 프로젝트 이름`, 오른쪽에 서버 연결, GPU 이름, GPU/VRAM/CPU/RAM 사용률(값 아래 6px 막대, 70% 초과 노랑, 90% 초과 빨강), 지금 GPU를 쓰는 작업, 라이트/다크 전환. **하단**: 시스템 메시지 줄. 주소는 `#/create`, `#/projects`, `#/projects/<id>/<구성품>`, `#/library`, `#/likes`, `#/settings`.

**만들기 화면**은 SongYUE2의 "만들기"처럼 `왼쪽 메뉴 | 작업 설정 패널 | 프로젝트 카드` 세 칸이다. 패널에는 새 프로젝트, 주제, 영상 크기(프리셋 드롭다운 + 직접 입력), 길이, 영상 모드, 오디오 원천, 이미지 모델, 접힌 "고급 옵션(Advanced)"이 있고 바로 저장된다. 카드 영역에는 탭(전체/완성본/작업 중/즐겨찾기), 검색, 정렬 아이콘 막대(MemoReader와 같은 아이콘: 수정 날짜 순(누르면 오름/내림 전환), 가나다순, 역순, 긴 영상 먼저, 즐겨찾기 먼저), 카드 목록이 있다. 카드의 이름을 누르면 그 프로젝트의 설정이 패널에 나타난다.

**프로젝트 카드**: 16:9 썸네일(완성본 재생 시간 표시, 누르면 카드 안에서 재생, 완성본이 없으면 정보 창), 제목과 주제 한 줄과 칩(완성/작업 중, 단계 진행, 날짜), 즐겨찾기 / 프로젝트 열기 / 더 보기 버튼과 재생 시간. 프로젝트 화면에서는 카드를 누르면 프로젝트가 열리고, 라이브러리·좋아요에서는 정보를 누르면 **정보 창**(줄거리, 시나리오, 대본, 이미지, 동영상 보기)이 열린다.

**프로젝트 화면**(`프로젝트` 메뉴): `왼쪽 메뉴 | 프로젝트 목록 | 상세` 세 칸이다. **가운데**에 프로젝트 카드가 세로로 쌓인 스크롤 목록(검색, 정렬 아이콘 막대, 새 프로젝트 버튼)이 있고, 카드를 고르면 **오른쪽 위에 구성품 탭**(제목 / 줄거리 / 시나리오 / 대본 / 이미지 / 오디오 / 동영상, 있으면 확인 표시나 개수)이 가로로 나타난다. 탭을 누르면 그 아래 본 화면에 해당 구성품을 **확인하고 고치는** 화면이 열린다.
- 제목과 주제: 제목은 `studio/meta.json`에 저장(폴더 이름은 그대로), 주제는 `studio/topic.md`.
- 줄거리: `studio/synopsis.md` 편집.
- 시나리오: `artifacts/scene_plan.json`의 장면(종류, 시작/끝, 설명)을 편집·추가·삭제. 스키마가 정해진 항목만 허용하므로 편집하지 않는 항목(`script_section_id` 등)은 그대로 보존한다. 장면은 `script_section_id`로 대본 구간과 이어진다.
- 대본: `artifacts/script.json`의 구간(대사, 시작/끝)을 편집. 한국어 음성 속도를 실측해(33글자 5.04초, 초당 약 6.5글자) 구간보다 긴 대사에 경고를 보여 준다.
- 이미지 / 오디오 / 동영상: 파일 목록(보기, 재생)과 "새로 만들기" 폼(이미지는 Krea, 오디오는 Qwen3-TTS 음성, 동영상은 I2V / FL2V / S2V). 만드는 중이거나 실패한 작업은 폼 아래에 표시된다.

### 4.2 설정의 배치 (요구 2) — 시작 페이지와 설정 화면을 나누는 기준

**기준: 영상마다 바꾸는 것은 시작(작업) 페이지, 환경과 품질 기본값처럼 가끔 바꾸는 것은 설정 화면.** 시작 페이지의 값은 프로젝트에 저장(`studio/settings.json`)되고, 설정 화면의 값은 전역 기본값(`data/settings.json`)이다. 프로젝트 값이 없으면 전역 기본값을 따른다.

**시작(작업) 페이지 — 자주 바꾼다**

| 항목 | 값 | 비고 |
|---|---|---|
| 주제 | 직접 입력 / 주제 제안 / 자동(후보 풀 랜덤) | 매번 입력 |
| 영상 크기 | **프리셋 드롭다운**: 가로 16:9(1080p, 720p, 시안), 와이드 21:9(시네마), 가로 4:3, 세로 9:16(쇼츠·릴스 1080p, 720p), 세로 4:5(인스타), 세로 3:4, 정사각 1:1(1080, 720) 11개 + **직접 입력**(생성 크기와 최종 크기를 가로×세로로 임의 지정, 32의 배수) | 표시는 "생성 736×416 → 최종 1920×1088"만 한다. 이미지 크기는 최종 크기에 맞춰 자동으로 정한다(긴 변 1920 이하). 생성과 최종의 모양이 3% 넘게 다르면 잘림 경고, 시험하지 않은 프리셋은 "시험 전"으로 표시(현재 16:9 1080p만 시험함) |
| 목표 길이 | 초 단위 입력 | 17k+5 프레임 격자(24fps)로 자동 보정해 표시 |
| 영상 모드 | T2V / I2V(첫 이미지) / FL2V(첫+끝) / R2V(참조) | 기본값 한 개 + 장면 카드에서 장면별로 바꿈 |
| 오디오 원천 | 입력 노래 업로드 / SongYUE2 생성 / H3 자체 오디오 / S2V | 노래 파일 선택과 가사/스타일 입력이 여기 있다 |
| 이미지 모델 | Krea 2 Turbo(기본) / H3 스틸 | 기본값이 거의 고정이므로 한 줄 선택으로만 둔다 |
| 장면별 값 | 이미지 프롬프트, 시드 고정/변경, 영상 모드 | 스토리보드/영상 화면의 장면 카드 |
| 고급 옵션 (Advanced, 접힘) | 아래 "설정 화면" 항목 중 이 프로젝트에서만 바꾸고 싶은 것(확대 방식, 최종 FPS, 노래 저장 형식) | 평소에는 접혀 있고 기본값을 따른다 |

**설정 화면 — 가끔 바꾼다 (전역 기본값)**

| 그룹 | 항목 |
|---|---|
| 이미지 | 기본 이미지 모델, 크기 프리셋 정의(16:9/9:16/1:1별 크기), 직접 입력 허용(32의 배수) |
| 영상 | 영상 모델(MiniMax H3 Turbo), 생성 해상도(기본 736×416), 최종 해상도(기본 1920×1088), 확대 방식(RTX 2pass / 없음 / Lanczos), 최종 FPS(ffmpeg 변환), 클립 길이 단위 |
| 오디오 | 기본 오디오 원천, 노래 저장 형식(flac), 음성(qwen3_tts, Sohee, ko) |
| LLM | **설정 화면의 "대본 도우미"에서 SongYUE2처럼 타일로 선택**(Claude CLI / Codex CLI / OpenCode CLI / Ollama, 사용 가능 여부 표시), 모델 이름(Ollama는 연결 주소와 설치된 모델), 폴백 순서, 호출 제한 시간. "저장 후 연결 확인" 버튼 |
| 연결 | SongYUE2 주소(4311), ComfyUI 주소(8190), OpenMontage 폴더, ffmpeg 경로 |
| 폴더 | **프로젝트 폴더, 입력 폴더(가져올 노래·참조 이미지/영상), 출력 폴더(내보낸 완성본)**. SongYUE2처럼 라벨 위 입력칸에 기본값을 연한 글씨로 보여 주고, 폴더가 있는지 표시한다. 상대 경로는 앱 폴더 기준이며 저장하면 입력/출력 폴더를 만든다(기존 파일은 옮기지 않음) |
| 기타 | 주제 후보 풀(`direction-pool.json`) 편집 |

**나누는 규칙(새 항목을 추가할 때)**
1. 영상마다 답이 달라지는 항목이면 시작 페이지, 한 번 정하면 거의 안 바뀌는 항목이면 설정 화면.
2. 시작 페이지는 항목을 5~7개 안쪽으로 유지한다(현재 5개). 넘치면 가장 덜 바꾸는 항목을 "고급 옵션"으로 내린다. LLM 선택은 시작 페이지가 아니라 설정 화면에서만 한다.
3. 같은 항목을 두 곳에서 따로 저장하지 않는다. 시작 페이지는 항상 "프로젝트 값 → 없으면 전역 기본값" 순으로 읽고, 어느 쪽을 쓰는지 화면에 표시한다.
4. 사용자가 시작 페이지에서 쓰는 횟수를 보고 항목의 위치를 옮긴다(P1에서는 위 표를 초기값으로 한다).

### 4.3 시나리오 (요구 3)
1. **주제**: 직접 입력 / "주제 제안" / **자동**(MusicAutomation의 자동 곡 방식처럼 후보 풀에서 랜덤 선택).
2. **전체 줄거리**: 주제에서 LLM이 작성하거나 직접 입력. 결과는 `studio/synopsis.md`.
3. **시나리오(장면 구성)**: 줄거리(수정본 포함)를 입력으로 LLM이 `scene_plan` JSON을 만든다. 장면마다 `id`, `type`, `description`, `start_seconds`, `end_seconds`. 장면 길이는 영상 클립 단위(H3 약 5초 기준)에 맞춘다.
4. **시간별 대본**: 시나리오를 입력으로 LLM이 `script` JSON을 만든다. `title`, `total_duration_seconds`, `sections[]`(`id`, `text`, `start_seconds`, `end_seconds`). 섹션 `id`는 장면 `id`와 맞춘다(스키마가 추가 필드를 허용하는지는 P3에서 확인).
5. 각 단계는 **생성 → 사람이 수정 → 승인** 순서이고, 다음 단계는 승인된 파일만 입력으로 쓴다. 구조화 출력은 스키마와 시간 검증(장면이 끊김 없이 이어지는지, 대사 길이가 구간에 맞는지)을 통과해야 하며, 실패하면 이유를 알려 최대 3번 다시 요청한다.
6. LLM 선택은 상단 메뉴. 모든 호출은 텍스트 호출이며 도구 권한은 없다. 구조화 출력 단계는 CLI 제공자를 우선하고 Ollama는 사용자가 고를 때만 쓴다.

### 4.4 장면 이미지 (요구 4)
장면 계획의 장면별 이미지 프롬프트를 LLM이 작성(시나리오 단계의 한 필드, 텍스트가 그림에 글자로 그려지지 않도록 영어 스타일 단어 위주) → 스토리보드 화면에 카드로 표시. 카드마다 프롬프트 수정, 이미지 재생성(`comfyui_krea_image` 직접 실행), 교체(업로드)가 가능. 다음 단계로 넘기려면 에셋 단계 승인.

### 4.5 영상과 오디오 (요구 5)
- 장면 이미지 → `h3_local_video`(저해상도 생성 후 RTX 확대). 모드 T2V/I2V/FL2V/R2V.
- 오디오: 입력된 오디오가 있으면 그것을 사용. 없으면 SongYUE2로 노래 생성(`songyue_music`)하거나 H3 자체 오디오 사용.
- **S2V(Sound2Video, 립싱크)**: H3의 `MiniMaxH3AddGuide`로 음성을 첫 프레임 위치에 고정하면 입 모양이 맞춰진다(사용자가 시험 영상으로 확인: "립싱크는 아주 잘 된다"). 뮤직비디오는 노래를 5~15초 구간으로 나눠 클립을 만들고 이어 붙인다. 구간 경계는 SongYUE2의 가사 싱크(`POST /api/projects/:id/lyrics-sync`, 줄 단위 시간)를 쓰고, 보컬만 넣는 편이 유리할 것으로 예상하며(미확인) SongYUE2의 보컬 분리(`/stems`, `mode: "vocal"`)를 시험한다.
- 최종 합성: OpenMontage compose(Remotion)로 자막, 음악을 얹어 `renders/final.mp4`.

### 4.6 폴더와 라이브러리 (요구 6)
위 3절의 폴더 구조가 곧 라이브러리. 라이브러리 화면은 프로젝트 목록(포스터, 길이, 단계 상태)과 파일 단위 보기/수정(주제, 줄거리, 시나리오, 대본 텍스트, 이미지, 오디오, 영상)을 제공한다. 파일 탐색기에서 직접 고쳐도 반영된다(파일 감시).

## 5. OpenMontage 쪽에서 해야 할 확장
- `h3_local_video`: 현재 T2V/I2V만 지원 → **FL2V(`last_frame`), R2V(참조 영상/이미지/오디오), 오디오 고정(`MiniMaxH3AddGuide`, S2V)** 입력 추가.
- 첫 프레임 이미지 비율이 달라서 약 3% 찌그러지는 문제 수정(생성 해상도에 맞춰 이미지 크기 보정).
- 이 앱은 OpenMontage 파이프라인(research/proposal/...)과 에이전트를 쓰지 않으므로, 확장은 도구 쪽만 한다.

## 6. 가장 큰 위험과 먼저 할 시험
스파이크(`docs/spike-agent.md`, 2026-10-19) 결과 비대화형 에이전트 실행은 동작하지만(승인 지점 정지, 같은 세션 재개) 도구 허용 목록이 보호 장치가 되지 못했다(`python` 접두사 허용은 임의 코드 실행과 같고, `Write`는 프로젝트 밖에도 써진다). 그래서 에이전트 방식은 채택하지 않았다. 남은 위험:
1. **LLM이 시간을 틀린다**: 장면 길이와 대사 길이가 맞지 않거나 장면이 끊긴다 → 스키마와 시간 검증 + 사유를 알려 재요청(최대 3번). 한국어 음성(qwen3_tts)의 글자당 길이는 P3에서 실측한다.
2. **LLM 호출 실패/한도**: Codex는 ChatGPT 한도에 걸리면 다음 제공자로 넘어간다(MusicAutomation 체인). 실제로 답한 제공자를 상단에 표시한다.
3. **GPU 12GB 충돌**: 우리 작업, SongYUE2(한 번에 한 곡, 진행 중이면 409), OpenMontage 도구(ComfyUI 8190/8188)가 같은 GPU를 쓴다 → 락을 한 곳(`bridge/om_tool.py`의 락 파일)에 두고 SongYUE2의 `/api/generate/status`도 함께 확인한다.
4. **사용자 수정과 승인의 어긋남**: 승인 후 앞 단계 파일을 고치면 뒤 단계가 낡은 입력을 쓴다 → 승인 기록에 입력 파일의 해시를 남기고 달라지면 뒤 단계를 "다시 승인 필요"로 표시한다.
