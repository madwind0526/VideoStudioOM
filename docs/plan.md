## Wave 1 — S. 스파이크 (완료)

결과는 `docs/spike-agent.md`. 요약:

- `claude -p`로 승인 지점에서 정지하고 `--resume`으로 같은 세션 재개, 수정본 반영은 **가능**했다.
- 그러나 도구 허용 목록은 보호 장치가 되지 못했다. `Bash(python:*)` 허용은 임의 명령 실행과 같았고, `Write`는 프로젝트 밖에도 써졌으며 Windows에서 경로 제한 규칙 표기를 찾지 못했다.
- 그래서 **에이전트가 파이프라인을 돌리는 방식은 채택하지 않고**, 줄거리/시나리오/대본은 권한이 필요 없는 LLM 텍스트 호출로 만든다. 에이전트 방식은 대안으로 남긴다.
- OpenMontage 체크포인트: 파이프라인 이름 없이 `script`/`scene_plan`을 쓰는 것은 가능, 파이프라인을 지정하면 앞 단계(research, proposal) 체크포인트를 요구해 거부된다. 그래서 정본은 `artifacts/*.json` 파일로 한다.

## 공통 규칙과 품질 기준

- 코드 주석은 영어, UI는 한국어. 포트는 `C:\Claude\PORTS.md`. Node 백엔드는 dev에서 `node --watch`.
- 서버는 loopback(127.0.0.1)만 연다. 쓰기/실행 요청은 토큰을 요구하고 `Origin`/`Host`를 검사한다. 파일 API는 프로젝트 루트 밖 경로를 거부한다.
- 새 로직에는 `node --test` 테스트. 외부 호출(LLM, 도구, SongYUE2)은 가짜 실행기로 테스트하고, 실제 호출은 각 Wave 끝의 수동 확인 목록에 둔다.
- 각 Wave 끝에서 `memory-bank/CACHE.md`를 `knowledge/`로 flush하고 `STATE.md`를 갱신한다.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| LLM이 장면/대사 시간을 틀림 | 스키마 + 시간 규칙 검증, 사유를 알려 최대 3번 재요청, 대사 길이는 음성 실측 기준 |
| LLM 호출 실패, 구독 한도 | 폴백 체인, 실제로 답한 제공자 표시. 타임아웃과 프로세스 트리 종료 |
| 승인 후 앞 단계 수정으로 뒤 단계가 낡음 | 승인 기록에 입력 해시, 달라지면 다시 승인 필요 |
| GPU 12GB에서 작업 충돌(우리 작업, SongYUE2, OpenMontage 도구) | 락 파일 한 곳 + SongYUE2 상태/409 확인, 진행 중 409 |
| 브라우저의 다른 페이지나 tailnet 기기가 API를 호출 | `Origin`/`Host` 검사 + 토큰, loopback만 열기 |
| 같은 파일을 GUI와 탐색기에서 동시에 수정 | 수정 시각 비교(충돌이면 409) |
| OpenMontage 업스트림 변경과 우리 확장의 충돌 | 확장은 새 파일 우선, 로컬 브랜치 `videostudio-local`(기존 로컬 변경은 2026-10-19에 첫 커밋 `57c1382`로 보관)에 작은 커밋으로 쌓고 `docs/openmontage-changes.md`에 기록. 업스트림을 받을 때는 이 브랜치에서 리베이스 |
| 립싱크가 노래(음정 있는 발성)에서 품질 저하 | P5에서 시험 후 보컬 분리/구간 길이 결정, 실패 시 음성 모드만 제공 |
