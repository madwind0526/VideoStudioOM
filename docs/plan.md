## Wave 1 — S. 스파이크 (에이전트 CLI 비대화형 실행)

**목표**: "설정 → 에이전트 실행 → 승인 지점에서 정지 → GUI가 파일 수정/승인 → 같은 세션으로 재개"가 가능한지 확인한다.

| # | 작업 | 확인할 것 |
|---|---|---|
| S1 | `claude -p`를 OpenMontage 폴더에서 실행(짧은 주제, 제안 단계까지) | 프로젝트 폴더/`checkpoint_*.json`이 생기는가, 승인 지점에서 `awaiting_human`으로 끝나는가 |
| S2 | 승인 기록(`lib.checkpoint.write_checkpoint`, `human_approved=True`) 후 `--resume <session>`으로 재개 | 이전 맥락을 유지하고 다음 단계로 가는가 |
| S3 | 도구 허용 목록(Bash, Read, Write, Edit, WebSearch) 지정 | 승인 질문 없이 끝까지 가는가, 허용 밖 동작은 막히는가 |
| S4 | `script.json`의 한 문장을 수정한 뒤 재개 | 이후 단계(`scene_plan`)가 수정본을 반영하는가 |
| S5 | `codex exec`, `opencode run`으로 S1~S2 반복 | 세 CLI의 실행/재개 방식 차이 |
| S6 | 소요 시간과 구독 사용량 기록 | 한 단계당 대략 비용 |

**완료 기준**: `docs/spike-agent.md`에 명령, 관찰, 결론(채택할 실행 모델)이 있다. 실패 시 대안(에이전트는 대화형 세션, GUI는 파일 편집/확인만)으로 설계를 수정한다.
**주의**: 구독 사용량을 쓰므로 주제는 짧게, 시작 전에 사용자에게 알린다.

## 공통 규칙과 품질 기준

- 코드 주석은 영어, UI는 한국어. 포트는 `C:\Claude\PORTS.md`. Node 백엔드는 dev에서 `node --watch`.
- 서버는 loopback(127.0.0.1)만 연다. 파일 API는 프로젝트 루트 밖 경로를 거부한다.
- 새 로직에는 `node --test` 테스트. 외부 호출(에이전트, 도구, SongYUE2)은 가짜 실행기로 테스트하고, 실제 호출은 각 Wave 끝의 수동 확인 목록에 둔다.
- 각 Wave 끝에서 `memory-bank/CACHE.md`를 `knowledge/`로 flush하고 `STATE.md`를 갱신한다.
